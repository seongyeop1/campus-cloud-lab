# 설계 결정 기록

결정마다 무엇을 골랐고, 무엇을 버렸고, 왜 그랬는지 적는다. 바뀌면 지우지 말고 아래에 덧붙인다.

## 1. EC2 한 대 + Docker 컨테이너

- 고른 것: EC2 한 대에 학생 수만큼 컨테이너를 띄운다.
- 버린 것: EKS(컨트롤 플레인 시간 요금이 따로 붙음), 학생마다 EC2 한 대(비용이 학생 수에 비례), 가상 데스크톱 서비스(실습용으로는 무겁고 비쌈).
- 이유: 한 반 30명 규모에서는 한 대로 충분하고, 구조가 단순해 장애 지점이 적다. 더 커지면 4단계의 k3s 버전으로 넘어간다.

## 2. 웹 터미널: ttyd

- 고른 것: ttyd (바이너리 하나, 메모리 사용이 작음).
- 버린 것: code-server (편집기까지 되지만 학생당 메모리가 훨씬 큼).
- 이유: 리눅스 명령어 실습이 목적이라 터미널이면 충분하고, 같은 서버에 더 많은 학생을 올릴 수 있다.

## 3. 인증은 리버스 프록시(Caddy)에서

- 학생마다 계정을 따로 만든다. 서버에는 해시만 두고, 평문 비밀번호는 관리자에게 한 번만 전달한다.
- 학생 컨테이너는 바깥으로 포트를 열지 않는다. 바깥에서 들어오는 길은 프록시 하나뿐이다.

## 4. TLS

- 배포 모드: Caddy 자동 HTTPS. 도메인이 없으면 IP 기반 호스트명 서비스(예: sslip.io)를 쓴다.
- 자동 발급이 안 되는 환경을 대비해 Caddy 내부 인증서(`tls internal`)로 바꿀 수 있게 해 둔다.
- 로컬 모드: `http://localhost:8080`.

## 5. 학생 간 격리

- 학생 컨테이너마다 네트워크를 따로 둔다. 프록시만 모든 학생 네트워크에 붙는다.
- 메모리·CPU·PID 수를 제한해 한 학생이 서버를 독차지하지 못하게 한다.
- privileged, 호스트 네트워크, docker.sock 마운트는 쓰지 않는다.
- 실습에 sudo가 필요해서 컨테이너 안 root는 허용한다. 대신 Docker userns-remap으로 컨테이너 root가 호스트에서는 일반 사용자가 되게 한다.

## 6. 관리 접속과 인스턴스 보안

- SSH(22번)는 열지 않는다. 관리자는 SSM Session Manager로 접속한다.
- 인스턴스 역할에는 SSM에 필요한 권한(AmazonSSMManagedInstanceCore)만 준다.
- IMDSv2를 강제하고, 루트 볼륨은 암호화한다.
- 보안 그룹은 80/443만, 허용한 IP 대역에서만 연다.

## 7. 학생 데이터

- 학생 홈 디렉터리는 볼륨으로 남겨 수업이 끝나도 이어서 쓸 수 있게 한다.
- 학기가 끝나면 볼륨째 지운다. 특정 학생만 초기화하는 명령도 둔다.
